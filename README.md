# Wine Classifier

Учебный проект по классификации табличных данных. По 13 химическим показателям
модель определяет один из трёх классов вина. Это классификация сорта, а не оценка
качества, цены или вкуса. Названия сортов в используемой версии набора заменены
метками 0, 1 и 2.


## Данные

[Wine из scikit-learn](https://scikit-learn.org/stable/modules/generated/sklearn.datasets.load_wine.html)
содержит 178 образцов, 13 числовых признаков и 3 класса.
Примеры показателей: alcohol, malic_acid, ash, magnesium, color_intensity.
Источник — [UCI Wine](https://archive.ics.uci.edu/dataset/109/wine).
Набор встроен в библиотеку; скачивать CSV отдельно не нужно.
Пропусков нет, поэтому в этой версии не понадобилась их обработка.

## Как запустить

```bash
python -m venv .venv
source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python train.py
python predict.py
python -m unittest -v
```

`train.py` создаёт модель в `artifacts/model.joblib`, отчёт в `reports/metrics.json`
и пример входных данных `example.json`. Модель не хранится в Git: она заново
обучается при запуске. Зависимости зафиксированы по версиям прямых пакетов;
полного lock-файла транзитивных зависимостей нет.

Чтобы сделать предсказание для другого набора показателей:

```bash
python predict.py my_wine.json
```

Формат — как у `example.json`: все 13 показателей с теми же именами, единицами
и смыслом измерений, что в исходном наборе. Порядок полей не важен. Пропуски,
лишние поля и нечисловые значения отклоняются. Проверки не определяют, реалистичен
ли химический состав: необычные входы всё равно могут получить неверный класс.
Пример взят из test, его истинная метка — 0. Это проверка работы программы,
а не независимый эксперимент на новых данных.

## Что делает программа

1. Загружает данные и делит их на train/test в пропорции 80/20.
2. Сохраняет пропорции классов с помощью `stratify` и фиксирует `random_state=42`.
3. Обучает `DummyClassifier`, всегда предсказывающий самый частый класс train.
4. Обучает `StandardScaler` и логистическую регрессию в одном `Pipeline`.
5. Считает accuracy и матрицу ошибок на test, сохраняет модель и отчёт.

Алгоритм и параметры заданы заранее, подбора гиперпараметров нет. Поэтому здесь
используются две выборки. При добавлении подбора параметров нужна validation-выборка
или кросс-валидация внутри train; test должен остаться для финальной проверки.

## Результаты

Train: 142 образца. Test: 36 образцов.

| Модель | Accuracy | Верных ответов |
|---|---:|---:|
| Самый частый класс | 38,89% | 14 из 36 |
| Логистическая регрессия | 97,22% | 35 из 36 |

Матрица ошибок: строки — истинный класс, столбцы — предсказанный.

| Истинный класс | Предсказан 0 | Предсказан 1 | Предсказан 2 |
|---|---:|---:|---:|
| 0 | 12 | 0 | 0 |
| 1 | 0 | 14 | 0 |
| 2 | 0 | 1 | 9 |

Модель ошиблась на одном объекте класса 2, отнеся его к классу 1.
Подробные метрики и индексы разбиения — в [reports/metrics.json](reports/metrics.json).

Датасет маленький и хорошо подходит для простого учебного примера. Один ответ
на test меняет accuracy примерно на 2,78 процентного пункта. Один split не даёт
полной оценки устойчивости модели. Результат не гарантирует качество на образцах
из другой лаборатории или других сортах. Нельзя продолжать настраивать модель
по этому test и считать его независимым.
